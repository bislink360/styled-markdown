Saved Searches

Let users save a search with its filters and get notified when new results match. Targets the Q4 release.

Overview
Release Q4 2026
Health On track
Build progress 35%
Design Figma — Saved searches

Power users re-run the same 3–5 searches every day. Saving them removes ~40 seconds per search and lets us notify people when something new appears.

?Open question

Should saved searches be shareable with a team in v1, or only personal? Decision needed by 2026-10-10.

Requirements

Must have
  • Save the current query and filters with a name
  • List, rename and delete saved searches
  • Daily email digest when new results match
Nice to have
  • Share with a team
  • Slack notifications
Out of scope
  • Real-time push notifications
  • Saved searches on mobile (Q1 2027)

User flow

flowchart LR
    S[Search page] -->|Save search| N[Name it]
    N --> L[(Saved searches)]
    L -->|nightly job| J{New matches?}
    J -- yes --> E[Email digest]
    J -- no --> X[Do nothing]

API

Create
POST /v1/saved-searches
Content-Type: application/json

{ "name": "Open P1 bugs", "query": "priority:p1 state:open" }
Limits
  • 50 saved searches per user
  • Name ≤ 80 characters
  • Digest at 08:00 in the user’s time zone
⚠Breaking change

GET /v1/search will require the filters object instead of query-string filters. Clients must migrate before 2026-11-01.

🤖For agents: Implementation guidance
  • Store saved searches in the existing user_prefs Postgres schema; do not add a new database.
  • Reuse SearchQuery.parse() for validation — never hand-parse query strings.
  • Every new endpoint needs an OpenAPI entry in api/openapi.yaml and a contract test.
  • If the open question above is still unresolved, implement personal-only saved searches.
